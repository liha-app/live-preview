# Narration — Liha Live Preview, OpenAI WebMCP Challenge

American English. Calm, confident, a developer showing a colleague something
that works. Not an advertisement. Technical terms said clearly: **WebMCP**,
**CLI**, **DOM**, **CSS selector**, **structured**.

Timings are targets for the edit, not instructions to the narrator.

---

## 01 — hook · 0:00–0:16

> Design feedback usually reaches a developer as a screenshot and a sentence,
> and the first ten minutes go on working out what it pointed at.
>
> Liha Live Preview turns the review itself into something an agent can use —
> in the same browser tab the reviewer is looking at.

## 02 — publish · 0:16–0:38

> One command publishes a build to a URL that never changes.
>
> Every later version arrives at that same link, so nobody has to send a new
> one, and feedback stays attached to the version it was written on.
>
> The CLI packages the build, uploads it, and opens the stable preview as soon
> as it is ready.

## 03 — human review · 0:38–1:06

> A reviewer opens the link and clicks the thing they mean.
>
> Liha records the CSS selector, the tag, the text inside it, the viewport and
> the exact version — captured at the moment of the gesture, not guessed at
> afterwards against a page that has since changed.
>
> Each comment remains anchored to that element and the visual context in
> which it was written.

## 04 — the agent · 1:06–1:48

> This is the part WebMCP makes possible. The page publishes thirteen tools to
> the agent inside the same browser tab.
>
> First, the agent reads the open review as structured data, including the
> comment and its captured context.
>
> It then focuses that exact comment and brings the referenced element into
> view.
>
> Call three switches the preview to a 390-pixel mobile viewport, reproducing
> the exact width where the reviewer saw the layout problem in context.
>
> Call four reads the stylesheet behind that element and identifies the CSS
> rules controlling its padding and type size.
>
> Call five posts the proposed fix directly into the review thread.

## 05 — same URL · 1:48–2:08

> After fixing the source, the agent publishes again without creating a new
> URL.
>
> Version two arrives at the same preview, with every earlier comment still
> attached. The reviewer checks the change in context and resolves the
> feedback on the spot.

## 06 — a real product · 2:08–2:20

> Everything you have made or reviewed, in one place, with what other people
> said on it.
>
> There is no sign-up. An account appears the first time you do something, and
> signing in only carries it to your other browsers.

## 07 — closing · 2:20–2:34

> Humans know what feels wrong. Agents know how to change it.
>
> Liha Live Preview gives them the same page to work on — and the same link to
> come back to.
